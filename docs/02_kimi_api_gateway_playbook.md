# 02. Kimi/API Gateway 客户开发方案

## 定位

```text
面向 AI 应用团队和企业软件团队的模型 API 网关：
Kimi 接入、模型路由、fallback、成本控制、用量监控、团队额度和 AI 功能上线陪跑。
```

## 不要卖什么

不要卖：

- 裸 token。
- API key 转售。
- 低价模型额度。
- 无场景调用。

要卖：

- 成本优化。
- 稳定性。
- 接入速度。
- 用量控制。
- 账单和权限。
- 多模型 fallback。
- AI 功能上线。

## 4 个产品包

### 1. Kimi API 快速接入包

目标客户：

- 想接 Kimi 但没有时间研究文档的开发团队。

交付：

```text
OpenAI-compatible base_url 接入
Python/Node 示例
统一鉴权
基础限流
错误重试
用量统计
1 小时接入支持
```

卖点：

```text
当天接入，当天跑通。
```

### 2. 多模型网关 / Model Router

目标客户：

- AI 应用团队。
- SaaS 团队。
- 内部 AI 工具团队。

交付：

```text
Kimi + 其他模型统一 API
按任务路由模型
失败 fallback
成本上限
调用日志
延迟统计
质量反馈
团队 API key 管理
```

卖点：

```text
不要把业务绑死在一个模型上。
```

### 3. Token 成本体检 / Cost Audit

目标客户：

- 已有 AI 调用成本，但不知道为什么贵。

交付：

```text
分析 7-30 天调用日志
找出浪费 token 的 prompt
识别可缓存上下文
推荐大小模型路由策略
输出 before/after 成本报告
```

卖点：

```text
7 天内找到 20%-50% 的模型调用成本优化空间。
```

### 4. AI 功能上线陪跑包

目标客户：

- SaaS。
- 企业软件。
- 外包团队。
- 系统集成商。

交付：

```text
一个 AI 功能从 0 到上线
模型选择
prompt
接口
监控
成本控制
上线 checklist
```

卖点：

```text
不是卖 API，是帮你把 AI 功能上线。
```

## ICP 优先级

### 一级：AI 应用创业团队

触发信号：

- 官网已有 AI 功能。
- 招聘 LLM/RAG/Prompt 工程师。
- GitHub/文档里出现 OpenAI SDK、Kimi、Moonshot、base_url。
- 创始人发 AI demo。

主卖：

- 模型网关。
- 成本优化。
- Kimi/多模型迁移。

### 二级：SaaS/企业软件团队

痛点：

- 想加 AI，但不知道用哪个模型。
- 担心成本爆。
- 担心稳定性。
- 缺少 AI 接入经验。

主卖：

- AI 功能上线包。
- 用量/权限/风控。

### 三级：系统集成商/外包团队

痛点：

- 客户多。
- 项目交付压力大。
- 不想自己维护模型网关。
- 需要分账和白标。

主卖：

- 白标 API 网关。
- 客户分账。
- 额度管理。
- 技术支持。
