# 04. 90 天执行路线图

## 目标

90 天内验证一条可持续获客和交付路径：

```text
付费客户：10-20 个
MRR：¥50,000-¥200,000 或 $5,000-$30,000
匿名案例：3 个
主 ICP：1 个
主渠道：1 个
可复用交付流程：1 套
```

## 第 1 周：合规边界与定位

目标：

```text
从“卖 token”改成“卖模型网关/工作流基础设施”。
```

动作：

```text
1. 国内线只主打 Kimi/国产合规模型。
2. 海外线只服务支持地区 Codex/coding agent 客户。
3. 禁止账号、key、token 转售。
4. 写客户准入规则。
5. 写基础服务条款和风控红线。
6. 定义产品命名：
   - Kimi API Gateway
   - Model Router
   - LLM Cost Audit
   - Coding Agent Workflow Audit
```

输出：

```text
定位文案
合规红线
客户准入表
服务条款草案
```

## 第 2 周：最小 demo 和销售资产

目标：

```text
客户一看就知道你们卖的不是裸 token。
```

动作：

```text
1. landing page
2. Kimi API 接入文档
3. 成本计算器
4. demo dashboard
5. Coding Agent demo 页面
6. 3 个场景 demo
```

Kimi demo：

```text
长文档总结 + 成本统计
模型路由 + fallback
token 成本报告
```

Codex demo：

```text
issue -> PR draft
PR review
CI log analysis
```

## 第 3 周：建立 200 个高意向客户名单

目标：

```text
不海投，建立可评分客户池。
```

名单配额：

```text
AI 应用创业团队：80
SaaS/企业软件团队：50
系统集成商/外包团队：40
海外 SaaS/dev agency：30
```

每个客户记录：

```text
公司名
地区
联系人
角色
触发信号
当前痛点假设
适合产品包
预估付费能力
首条话术
下一步动作
```

## 第 4 周：第一轮获客实验

目标：

```text
20 个有效对话
5 个诊断/audit
2 个付费试点
```

每天动作：

```text
联系 20 个高分客户
约 2-3 个电话
做 1 个免费诊断/audit
发 1 条技术内容或案例片段
记录所有转化数据
```

每 3 天复盘：

```text
哪个 ICP 回复最高？
哪个痛点最打动？
哪个 offer 最容易推进？
客户拒绝原因是什么？
```

## 第 2 个月：设计合作伙伴试点

目标：

```text
签 3-5 个付费 design partners。
```

Kimi 试点包：

```text
周期：2 周
价格：¥3,000 - ¥20,000
交付：
1. API 接入
2. 用量 dashboard
3. 成本体检
4. fallback 配置
5. 1 个业务场景上线
6. 试点复盘报告
```

Codex 试点包：

```text
周期：2 周
价格：$500 - $3,000
交付：
1. 接入 GitHub/Linear/Slack 中的一个
2. 选择 10 个真实任务
3. agent 生成 PR draft/review/CI fix
4. 人类 review
5. 统计节省时间
6. 输出试点报告
```

## 第 2 个月后半：产品化

目标：

```text
把试点交付变成可重复流程。
```

Kimi 产品化：

```text
onboarding checklist
API key 管理
用量 dashboard
成本报告
预算上限
fallback 规则
异常报警
每周账单
```

Codex 产品化：

```text
repo 权限配置
issue 分类器
PR draft 模板
review 输出模板
CI log 分析模板
任务状态看板
每周工程效率报告
```

## 第 3 个月：加仓赢家渠道

目标：

```text
确定一个主 ICP 和一个主渠道。
```

如果私信有效：

```text
名单扩大到 1000 个
做 5 套 ICP 话术
加 SDR 或自动化辅助
```

如果开源工具有效：

```text
持续更新
写教程
发开发者社区
接入商业 gateway
```

如果系统集成商有效：

```text
做 partner program
白标后台
分润机制
交付手册
```

如果 dev agency 有效：

```text
做 agency 版本
多项目 dashboard
按项目/客户分组
白标周报
```

## 每周必做复盘

```text
渠道投入
线索数
有效对话
诊断数
试点数
成交数
客户质量
拒绝原因
下周加仓/减仓
```

## 90 天结束判断

继续加仓的条件：

```text
有明确付费客户
有可重复诊断/audit 流程
有 1 个渠道 CAC 可控
客户愿意续费
能形成真实案例
```

需要转向的信号：

```text
客户只关心 token 单价
诊断后没人愿意试点
交付无法复用
合规风险过高
毛利太低
没有复购
```
