# 05. 增长操作系统

## 核心思想

把找客户当成交易和组合管理，而不是销售列表硬扫。

每个渠道都是一笔策略：

```text
投入多少
回报多少
容量多大
边际 ROI 是否下降
客户质量如何
风险多高
```

## 每周增长会议

固定议程：

```text
1. 本周目标完成情况
2. 每个渠道数据
3. 最强 ICP
4. 最强话术
5. 客户拒绝原因
6. 试点交付结果
7. 下周加仓/减仓
```

## 渠道评分

每个渠道按 1-5 分打分：

```text
回复率
有效对话率
客户质量
成交可能性
容量
执行成本
品牌风险
合规风险
```

优先加仓：

```text
客户质量高
试点率高
可重复
风险低
```

优先砍掉：

```text
只带来低价客户
支持成本高
灰色需求多
没有复购可能
```

## 客户评分

每个客户按 5 个维度评分：

```text
痛感：1-5
付费能力：1-5
合规可做：1-5
7 天验证可能：1-5
案例传播价值：1-5
```

建议：

```text
18 分以上：优先联系
15-17 分：二线跟进
15 分以下：暂缓
```

## Proof artifact

每一次诊断/audit/试点都要生成一个结果物。

Kimi 线：

```text
token 成本报告
prompt 浪费点
模型路由建议
预计节省金额
fallback 成功率
调用延迟变化
```

Codex 线：

```text
处理任务数
生成 PR 数
被采纳 PR 数
节省工程师小时
失败任务原因
token 成本
人工 review 时间
```

这些结果物是下一轮获客内容，不只是交付文档。

## 内容节奏

每周至少：

```text
2 篇技术内容
1 个案例片段
1 个工具/模板更新
1 次社群互动
```

内容主题不要空泛，要直接回答客户问题：

```text
如何减少 token 成本
如何接 Kimi API
如何做模型 fallback
如何给客户分账
如何用 coding agent 修 CI
如何评估 repo 是否适合 coding agent
```

## 每周目标模板

```text
高意向联系：100
有效回复：10
诊断/audit：3
试点报价：2
付费试点：1
技术内容：2
案例/报告：1
```

## 决策规则

不要凭感觉加仓。看数据：

```text
如果一个渠道连续两周有效对话率高于 10%，加仓。
如果一个渠道连续两周客户质量低于 3 分，减仓。
如果一个 offer 诊断转试点低于 20%，重写 offer。
如果客户只问 token 单价，降低优先级。
如果客户愿意给日志/repo/真实任务，提升优先级。
```

## 团队分工

早期可以三个人分工：

```text
增长/销售：找客户、联系、约诊断、复盘渠道。
技术/交付：做 demo、接入、成本报告、coding audit。
产品/运营：整理案例、写内容、维护模板、做 dashboard。
```

一个人也可以做，但每天必须固定时间块：

```text
上午：找客户和联系
下午：诊断/交付
晚上：记录数据和写内容
```

## 不要做的事

```text
不要群发低质量广告
不要一开始追求大而全平台
不要服务灰色客户
不要只按 token 单价竞争
不要没有报告就结束试点
不要做完客户不沉淀案例
不要每周换方向但不看数据
```
